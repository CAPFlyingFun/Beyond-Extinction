# BEYOND EXTINCTION — CINEMATIC SCRIPT
## Map One — Hanifat · Chapters Two–Three · Day One

**Purpose:** shared story data for **both** builds — Godot 4.7 (`Beyond-Extinction`) and the TypeScript mobile build. The beats, dialogue, clip IDs, and cue order are identical across engines. Only the *rendering* differs.

**Source:** `BE_Chapters_1-3_Final.docx` (canonical). **All dialogue is verbatim.** Action lines are compressed to screenplay form. No story content added or removed.

---

## 1. HOW TO READ THIS

Each beat is a block:

```
### 2.3.B — CINEMATIC — MidpointCam
> camera  moment=midpoint
> say     clip=arr_sarah_04

ACTION LINE (what the player sees)

SARAH  (arr_sarah_04)
"Verbatim dialogue."
```

- `###` heading = **beat ID** — `chapter.scene.beat`. Use these as save/checkpoint keys.
- **CINEMATIC** = CameraDirector drives. Player input released.
- **PLAYABLE** = first-person control. Camera rigs off.
- `>` lines = **cues**, in execution order.
- `(clip_id)` after a speaker = the audio asset key. Same key feeds the game *and* the audiobook pipeline.

### Mode discipline
The game is first-person survival; the rigs are the cinematic layer. **Never mix them in one beat** — every block is either PLAYABLE or CINEMATIC. Transitions between the two always run through a `control` cue.

## 2. CAMERA RIG REFERENCE (existing — do not add new rigs)

| `moment` | Rig | Use |
|---|---|---|
| `establishing` / `default` | **CornerCam** | Fixed. Subject enters frame from distance. |
| `follow` | **FollowCam** | Trails/leads a moving actor. `lead=true` to precede. |
| `midpoint` | **MidpointCam** | Floats between two actors. Standard two-hander. |
| `orbit` | **OrbitCam** | Slow circle. Long static dialogue. |
| `climax` | **FramingCam** | Wide two-shot. Big reveals. |

`targets = {primary, secondary, weight}` — `weight` biases framing (0.7 = toward primary).

> **Beach/jungle port:** same five scripts, repositioned for the new geometry. Story data calls `"follow"` / `"orbit"` and never touches camera code — same contract as the lab.

## 7. ENGINE SPLIT — "same story, different visual methods"

Everything above is engine-neutral. These are the only places the two builds diverge:

| Cue | Godot 4.7 | TypeScript mobile |
|---|---|---|
| `camera` | CameraDirector → `Cam.cut(rig_id, targets)` | Same `moment` names → your own camera controller |
| `vfx` id=`slowmo` | `Engine.time_scale` | rAF delta scaling |
| `vfx` id=`screen_shake` | Camera3D offset noise | CSS transform / canvas offset |
| `vfx` id=`sky_saturate` | WorldEnvironment adjustment | shader uniform / CSS filter |
| `sfx` spatial | AudioStreamPlayer3D | stereo pan approximation |
| `control` mode=`fp` | first-person controller | touch look + virtual stick |
| `gate` type=`timed_jump` | input buffer window | tap window |

**Rule:** if a cue can't be done identically on mobile, **downgrade the method, never the beat**. `screen_shake` on the roar can be a cheap CSS jolt on mobile and full 3D noise in Godot — the player still feels the roar in both. The beat is canon; the technique isn't.
